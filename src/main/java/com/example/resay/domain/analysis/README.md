# Analysis

1:1 전사 데이터를 바탕으로 관계·상황별 대화 분석을 수행합니다.

분석 작업의 상태 관리, AI 분석 실행, 결과 저장을 담당합니다.

## 처리 흐름

```text
AnalysisRequestedEvent (화자 매핑 저장 커밋 후)
  -> 비동기 분석 파이프라인 시작
AnalysisSourceReader
  -> 정량 지표 계산
  -> 분석 입력 적합성 검증
  -> 정성 모델 분석
  -> AnalysisReportAssembler
  -> 분석 상태와 보고서 저장
  -> 성공 시 AnalysisCompletedEvent / 실패 시 AnalysisFailedEvent
  -> 보고서 조회
```

B는 전사 세그먼트와 두 화자의 역할·이름을 저장하는 트랜잭션 안에서
`AnalysisRequestedEvent`를 발행합니다. C는 해당 트랜잭션이 커밋된 후에만 이벤트를 받아
별도 스레드에서 분석을 시작합니다. 같은 녹음에 대한 중복 이벤트는 한 번만 분석합니다.

분석 실패 시 C는 실패 상태와 사유를 저장하고 `AnalysisFailedEvent`를 발행합니다.
Recording 상태 반영은 B가 해당 이벤트를 수신해 처리합니다.
분석 작업 생성 전 예상하지 못한 오류가 발생해도 실패 분석을 저장한 뒤 같은 이벤트를
발행합니다. 중복 분석 요청과 이미 완료·실패한 작업은 다시 실패 처리하지 않습니다.

사용자에게 전달하는 분석 실패 사유는 내부 오류를 노출하지 않도록 다음 네 가지로 정제합니다.

- `INSUFFICIENT_SPEAKER_DATA`: 필요한 두 화자의 발화가 없거나 발화량이 분석 기준에 미달
  - 부모·자녀 갈등은 단답 자체도 분석 대상이므로 두 역할의 유효 발화가 있으면 화자별 발화량 기준을 적용하지 않습니다.
- `EXTERNAL_SERVICE_UNAVAILABLE`: 분석 제공자의 일시적 장애, 네트워크 오류 또는 요청 제한
- `INVALID_ANALYSIS_RESPONSE`: 미완료 응답, 형식 오류 또는 서비스 규칙 검증 실패
- `PROCESSING_ERROR`: 인증·설정·저장 오류 등 사용자에게 세부 내용을 노출하지 않는 내부 오류

정제한 사유는 Recording에도 같은 이름으로 저장되어
`GET /api/v1/recordings/{recordingId}/status`의 `failureReason`으로 반환됩니다.
기존 `ANALYSIS_FAILED` 값은 이전에 저장된 데이터와의 호환을 위해 유지합니다.

입력 적합성 검증을 통과한 데이터만 정성 모델에 전달합니다. 저장되는 보고서는
`recordingInfo`, `quantitativeAnalysis`, `qualitativeAnalysis`로 구성됩니다.

## 분석 보고서 v11

LINER는 대화 요약, 타임라인, 주제, 화자별 캐릭터와 대화 방식, 관심 표현, 강한 표현,
T/F 반응 및 관계·상황별 분석을 구조화된 JSON으로 반환합니다. 모든 정성 관찰은 실제
발화 ID를 근거로 사용하며 서버가 존재 여부와 화자 일치 여부를 검증합니다.

런칭 중에는 응답 JSON을 해석할 수 있고 타임라인·주제의 근거로 화면을 구성할 수 있다면
세부 의미 검증 오류만으로 분석 전체를 실패시키지 않습니다. 대표 근거부터 제외하고, 그래도
검증되지 않으면 관계 요약·세부 지표·화자 경향·코칭을 제외한 핵심 보고서를 best-effort로
저장합니다. 외부 서비스 실패, JSON 형식 오류, 화면을 구성할 수 없는 핵심 구조 오류는 기존처럼
분석 실패로 처리합니다.

캐릭터 이름과 설명은 LINER에 각각 10자·20자 이내를 생성 목표로 요청합니다. 모델이 목표
길이를 조금 넘기더라도 서버는 분석을 실패시키거나 문구를 임의로 축약하지 않고, 생성된
문장을 보고서에 그대로 저장해 공개합니다.

주제별 실제 등장 구간(`timeRanges`), 턴 수, 발화 시간과 가장 오래 이야기한 주제는
LINER가 반환한 주제별 발화 ID를 사용해 서버가 계산합니다. 같은 주제가 대화 중간에
다시 등장하면 각 구간을 나누어 제공합니다. 관심도·표독력 점수와 T/F 비율은 성격이나
관계 전체에 대한 진단이 아니라 이번 대화에서 해당 표현이 나타난 정도를 의미합니다.

근거 발화 ID는 분석 검증과 계산을 위해 내부 보고서에 저장하며 공개 API에는 직접 노출하지
않습니다. 다만 Figma 보고서에서 실제 발화를 표시하는 항목은 `representativeEvidences`에
대표 근거를 별도로 저장해 공개합니다. 친구·연인 일상은 화자별 T/F 반응 예시, 연인 갈등은
놓친 말과 갈등 반응 경향, 부모 자녀 갈등은 놓친 말과 훈계로 바뀐 순간만 대상입니다.

대표 근거는 원본 `segmentId`, 화자 역할, 원문, 표시용 보정문과 발화 시간을 포함합니다.
표시용 보정문은 전체 대화 맥락상 명확한 음성 인식 오류만 최소한으로 수정하며 원본 전사
세그먼트는 변경하지 않습니다. 모델이 원문과 지나치게 다른 문장을 반환하면 서버가 원문으로
대체합니다. 선택된 근거는 보고서 JSON에 스냅샷으로 저장하므로 전사 원문이 삭제된 뒤에도
보고서에서 유지됩니다. 대화 개선 힌트와 다시 대화하기 문장은 실제 근거가 아닌 생성 제안으로
구분합니다.

화자별 대화 방식인 `speakerInsights.patterns`에는 각 패턴의 전체 발생 횟수인 `count`와
화면에 문장 칩으로 표시할 대표 발화 `evidenceQuotes`를 최대 3개까지 제공합니다. 대표 발화가
잘못 선택되면 같은 패턴의 유효한 근거 발화로 대체하며 패턴과 전체 분석은 유지합니다. 실제
근거가 전혀 없는 부재 관찰은 패턴 목록에서 제외합니다. 이전 보고서는 빈 배열을 반환합니다.

피그마 보고서의 세부 표현 지표는 `reportMetrics`로 제공합니다. `COUNT`는 근거로 연결된
서로 다른 발화 수를 서버가 확정하며, `PERCENT`는 성격이나 관계 전체의 수치가 아니라 이번
대화에서 해당 표현이 관찰된 상대적 정도에 대한 모델 추정치입니다. `relationshipSummary`는
두 사람의 이번 대화 조합을 요약하고, 갈등 시나리오는 화자별 `speakerTendencies`와 각 화자별
세 단계의 `coachingSuggestions`를 추가로 제공합니다. 각 제안의 `speakerRole`은 개선 문장을
직접 말할 화자를 나타냅니다. 개선 문장의 `suggestedPhrase`는 원문 인용이 아닌
생성 제안이며 각 단계의 `evidenceQuotes`에는 제안이 필요한 실제 발화를 보고서와 함께
최대 3개까지 스냅샷으로 저장해 제공합니다. 부모·자녀 갈등의 세 단계는 상대 입장 확인, 걱정과 필요 설명, 구체적인 다음
행동 합의 순서로 제공하며 서버가 화자와 `order` 순으로 정렬합니다. 부모·자녀 갈등에서는 다른 부가
항목의 검증 실패로 `coachingSuggestions`를 제거하지 않으며, 모델 응답이 누락되거나 형식이
잘못된 경우에도 갈등 주제와 유효한 근거 발화를 사용한 세 단계 안전 대안을 제공합니다.

연인 일상 보고서는 `speakerAffectionSummaries`에 `SELF`와 `PARTNER`의 애정 표현 요약을
각각 제공합니다. 각 항목의 제목과 설명은 해당 화자의 표현 및 화자별 애정 지표만 바탕으로
생성하며, 공개 응답에서는 근거 발화 ID를 제외하고 `speakerRole`, `title`, `description`을
제공합니다. 다른 시나리오와 이 필드가 없던 이전 보고서는 빈 배열을 반환합니다.

화면에 표시하는 화자별 `PERCENT` 지표는 대화 유형마다 다음 네 개를 고정된 순서로
제공합니다. 모델이 일부 항목을 누락하면 서버가 해당 항목을 `0%`로 보완하므로 보고서의
세부 지표 영역은 항상 네 항목을 표시할 수 있습니다.

- 친구 일상: `SWEAR_WORD`, `DIRECTNESS`, `EXPRESSION_INTENSITY`, `SOFTENING_EXPRESSION`
- 연인 일상: `DIRECT_AFFECTION`, `CARING_EXPRESSION`, `COMPLIMENT_OR_ENCOURAGEMENT`, `AFFECTIONATE_ADDRESS`
- 연인 갈등: `DIRECT_EXPRESSION`, `ASSERTIVE_EXPRESSION`, `SOFTENING_EXPRESSION`, `RECOVERY_EXPRESSION`
- 부모·자녀 갈등: `ADVICE`, `ASSERTIVE_EXPRESSION`, `EMOTION_CHECK`, `SOFTENING_EXPRESSION`

친구 일상의 비속어 칩은 `spicinessInsights.swearWords`로 제공합니다. 각 항목은 분석 결과에
저장된 원문 `expression`과 등장 `count`를 포함하며, 서버에서 검열하거나 마스킹하지 않습니다.
비속어가 없으면 빈 배열을 반환하고 발화 세그먼트 ID는 공개 응답에 포함하지 않습니다.

관심도·표독력·T/F 비율과 PERCENT 지표는 5점 단위로 반올림하지 않고 근거 발화 수, 표현
종류, 대화 구간 분포와 강도를 바탕으로 1점 단위 정수를 요청합니다. 점수를 다양하게 보이게
하기 위한 임의 보정은 하지 않습니다.

연인 갈등의 `POSITION_EXPLANATION`, `REBUTTAL`, `AVOIDANCE`, `APOLOGY`, `YIELDING`
COUNT 지표에는 화면 표시용 대표 발화를 최대 3개까지 `evidenceQuotes`로 제공합니다. `value`는
전체 발생 횟수이고 대표 발화 개수와 같지 않을 수 있습니다. 대표 발화도 원문과 최소 보정문,
화자와 발화 시간을 보고서에 스냅샷으로 저장합니다. 잘못 선택된 대표 발화는 해당 문장만
제외하며 지표와 전체 분석을 실패시키지 않습니다. 이전 보고서와 미지원 지표는 빈 배열을
반환합니다.

부모·자녀 갈등의 COUNT 지표도 값이 0보다 크면 화면 표시용 대표 발화를 최대 3개까지
`evidenceQuotes`로 제공합니다. 값이 0인 지표와 PERCENT 지표는 빈 배열을 반환합니다.

녹음 일시(`recordedAt`)와 전체 대화 턴 수(`totalTurnCount`)는 모델이 추정하지 않고 녹음
메타데이터와 화자 전환을 기준으로 서버가 계산합니다. 세부 관찰에는 근거 발화 수를 `count`로
공개해 화면에서 유형별 횟수를 표시할 수 있습니다. 녹음 전체 길이는
`recordingInfo.durationMs`와 화면 표시용 `recordingInfo.durationSeconds`로 제공하며, 화자별
실제 발화 시간 합계와 구분합니다.

`recordingInfo.speakers`에는 화자 역할과 사용자가 입력한 이름을 저장해 조회 API에
제공합니다. 이름은 화면 표시용 메타데이터이며 LINER 요청에는 포함하지 않습니다.

애착 유형이나 정신 상태, 이른바 멘헤라 지수는 전사만으로 신뢰성 있게 판단할 수 없고 사용자에게
진단처럼 오해될 수 있어 제공하지 않습니다. 실제 발화로 확인할 수 없는 침묵도 지표에서 제외합니다.
스토리 공유 여부와 공유 UI는 분석 도메인의 책임에 포함하지 않습니다.

## 분석 보고서 조회

- `GET /api/v1/analyses?page=0&size=10`: 로그인 사용자의 분석 목록을 최신순으로 조회
- `GET /api/v1/analyses/summary`: 최근 완료 분석 5개의 개인화 대화 습관 요약 조회
- `GET /api/v1/analyses/{recordingId}`: 로그인 사용자가 소유한 녹음의 분석 상태와 보고서 조회
- `DELETE /api/v1/analyses/{recordingId}`: 로그인 사용자가 소유한 완료·실패 분석 결과 삭제

목록 API는 녹음 메타데이터와 분석 상태만 반환하고 전체 보고서 JSON은 조회하지 않습니다.
페이지 크기는 1 이상 50 이하이며, 분석이 시작된 녹음만 목록에 포함됩니다.

분석 중이거나 실패한 작업은 상태만 반환하고, 완료된 작업만 보고서를 포함합니다. 다른
사용자의 녹음은 조회할 수 없습니다.

개인화 요약은 본인 화자의 자주 쓰는 표현, 비속어 사용률, 평균 발화 길이, 말하기 속도와
분석별 말하기 비중을 서버에서 집계합니다. 평균 발화 길이는 최근 분석별 평균을 다시
평균하지 않고 본인의 전체 발화 시간 합계를 전체 발화 수 합계로 나눈 가중 평균입니다.
유효한 발화가 없으면 `averageUtteranceDurationMs`는 `null`을 반환합니다. 비속어 사용률은
본인 발화의 공백 기준 어절 수 대비 비속어 등장 횟수이며, 삭제된 분석은 다음 요약
조회부터 자동으로 제외됩니다.

말하기 속도는 최근 분석의 한글 음절 수를 실제 발화 구간으로 나눈 초당 음절 수입니다.
한국어 2인 대화 연구에서 확인된 평균 5.79음절/초를 비교 기준으로 사용합니다. 서비스 표시
구간은 5.0 미만 `RELAXED`, 5.0 이상 6.5 이하 `TYPICAL`, 6.5 초과 `FAST`이며 임상적
정상·비정상 판정이 아니라 이번 대화에서 관찰된 속도를 설명하기 위한 구간입니다.

개별 보고서의 `quantitativeAnalysis.speakers`에도 화자별 초당 음절 수와 함께
`referenceSyllablesPerSecond`와 `speakingSpeedDifferencePercent`를 제공합니다. 보고서와
개인화 요약 모두 한국어 평균 5.79음절/초를 같은 기준으로 사용하며, 양수는 평균보다 빠름,
음수는 평균보다 느림을 뜻합니다.
화면에서는 음수 기호를 직접 노출하지 않고 절댓값과 방향을 조합해 `13% 느림`, `12% 빠름`처럼
표시하며, 차이가 -1% 이상 1% 이하이면 `평균과 비슷함`으로 표시합니다. 각 화자를 평균과
독립적으로 비교하므로 두 화자가 모두 기준보다 빠르거나 모두 느린 결과가 나올 수 있습니다.
기존 화자 간 비교값인
`speakingSpeedComparison`과 화자별 `speakingSpeedDirection`은 하위 호환을 위해 유지합니다.

기준 자료: 고려대학교 「한국어 2인 대화의 말차례 조직 양상」
(DOI: 10.23186/korea.000000280371.11009.0000382)

삭제 API는 분석 결과와 캐릭터 이미지 데이터만 삭제하며 녹음, 음성 파일, 전사 결과는
유지합니다. 분석 또는 캐릭터 이미지 생성이 진행 중인 경우에는 삭제할 수 없습니다.

## 로컬 목업 실행

B 전사 도메인이 연결되기 전까지 `local`, `mock` 프로필에서는 클래스패스의 목업 전사 데이터를
`MockAnalysisSourceReader`가 공급합니다.

- `POST /api/v1/mock/analyses`: 시나리오를 선택해 목업 보고서 생성
- `GET /api/v1/mock/analyses/{recordingId}`: 생성된 목업 보고서 조회

기본값은 비용이 발생하지 않는 목업 정성 모델입니다. 실제 LINER 호출을 확인할 때는
`ANALYSIS_MOCK_MODEL_ENABLED=false`와 `LINER_API_KEY`를 설정합니다. 목업 컨트롤러와 데이터
공급자는 `local`, `mock` 프로필에서만 등록됩니다.

MySQL 없이 IntelliJ에서 전체 애플리케이션을 실행할 때는 `mock` 프로필을 사용합니다. 이
프로필은 개발용 H2 인메모리 DB를 사용하므로 앱을 종료하면 가입 정보와 보고서가 사라집니다.
